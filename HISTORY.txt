2026-11-07  RC2 — TJCScaler component and Lazarus packages (R2-02)
--------------------------------------------------------------------------------

Scaler core
  - No changes. JCUIScaler.pas and the .inc files are identical to RC1.2.

Risk check (Risk Analysis, section 2 and the RC1.2 rule)
  The component is an integration layer only: it hooks the owner form's
  events solely to call the public methods of TJCUIScaler. It registers
  nothing on the form's controls, the core and its object model are
  untouched, and the core's lifetime is that of the component (owned by the
  form).

New: source/JCUIScalerComponent.pas (LCL only)
  - TJCScaler = class(TComponent), holds a TJCUIScaler.
    Class name chosen so that the default instance name on a form is short
    (JCScaler1). The scaler core keeps its name TJCUIScaler: it is used in
    production applications with the manual integration and must stay
    compatible; the core works without the component.
  - Loaded: Attach — ScalerInit(Owner form), then the published properties
    SkipBevelScaling and ResetOnShow are applied (after ScalerInit, which
    resets them).
  - OnShow: chained in Attach (LCL has no handler list for OnShow); the
    application's own OnShow runs first, then ScalerOnShow — the same order
    as the manual integration in the demo.
  - Resize: AddHandlerOnResize on the owner form (LCL handler list); the
    application's own OnResize stays untouched and runs first.
  - Published properties SkipBevelScaling and ResetOnShow are linked to the
    scaler object: set in the Object Inspector (streamed, applied after
    ScalerInit) or changed in code at any time; after Attach they are read
    from and written to the scaler directly.
  - Published events (default empty), Sender = the component:
      BeforeShow, AfterShow, BeforeResize, AfterResize
    Order on show:   form OnShow -> BeforeShow -> ScalerOnShow -> AfterShow
    Order on resize: form OnResize -> BeforeResize -> ScalerOnResize ->
                     AfterResize
    AfterResize is the place for adjustments the scaler does not make (fonts,
    controls outside the model, custom drawing); geometry of model controls
    set in BeforeResize is overwritten by the scaler.
  - Protected virtual DoShow and DoResize (default: Before* event, scaler,
    After* event) for descendants; protected property Attached.
  - Public: Attach (for components created in code, or after the application
    replaced OnShow at run time), Rescale (= ScalerOnResize; e.g. from
    TPageControl.OnChange on Windows), RestoreInitialScale.
  - One component per form; owner must be a TForm, otherwise inactive.
  - Destroy: unhooks OnShow and the resize handler unless the form itself is
    being destroyed.

New: source/design/JCUIScalerReg.pas, source/design/jcuiscaler_icons.res
  - Registers TJCScaler on palette page "JCUI" with the 24/36/48 px
    icons (TJCSCALER, _150, _200).

New: packages/lazarus
  - jcuiscaler_rt.lpk   (RunTime): JCUIScaler + .inc files +
    JCUIScalerComponent; requires LCL.
  - jcuiscaler_dsgn.lpk (DesignTime): JCUIScalerReg + icons; requires
    jcuiscaler_rt and IDEIntf. Install this one in the IDE.
  - Sources are referenced from ../../source (no copies).

Demo

Verification (FPC 3.2.2 / LCL 3.0, GTK2, 96 DPI)
  - Both packages compile with lazbuild; no warnings from JCUIScaler units.

2026-11-07  Demo update + scrollbar recommendation (no library changes)
--------------------------------------------------------------------------------

Library
  - No changes. Sources are identical to RC1.2.

Known behaviour — TListView on hidden tab sheets
  TListView is a native widgetset control. While its tab sheet is hidden it
  reports a ClientWidth that does not include its vertical scrollbar. Columns
  scaled at that moment are too wide by the scrollbar width until the next
  form resize (confirmed on Windows and GTK2; GTK2 measured: ClientWidth 451
  while hidden, 435 once shown). With a horizontal scrollbar allowed, this
  shows up as a horizontal scrollbar after the tab is shown.

  LCL grids (TStringGrid, TDBGrid) are not affected: they are drawn by the LCL
  and manage their own scrollbars, so ClientWidth is correct even while hidden
  (GTK2 measured with ssAutoBoth, ssVertical and ssBoth, 6 and 60 rows).

Recommendation — ScrollBars = ssVertical for TListView (vsReport)
  JCUIScaler fits the columns to the control width, so a horizontal scrollbar
  is never needed. With ScrollBars = ssVertical the temporary excess after a
  hidden-tab resize stays under the vertical scrollbar / right edge (only the
  empty end of the last column is clipped) and no horizontal scrollbar
  appears. No code, no extra calls. Confirmed on Windows and GTK2.
  The same setting is a sensible default for grids scaled by JCUIScaler,
  although grids do not have the hidden-tab issue.

  Optional, Windows only — exact widths immediately after a tab change: call
  FScaler.ScalerOnResize from TPageControl.OnChange. ScalerOnResize recomputes
  everything from the reference model, so the call is deterministic and safe
  at an unchanged form size. On GTK2 it has no effect: TTabSheet.OnShow and
  TPageControl.OnChange fire before the new tab is laid out.

  Rejected alternatives:
  - OnResize handler registered by the scaler on every TListView: makes the
    scaler react to control events outside its three explicit calls and ties
    its lifetime to the controls — contrary to the design.
  - Deferred call (Application.QueueAsyncCall from OnChange): works on GTK2,
    but the tab is first painted with the wrong columns and then corrected
    (visible flicker).
  - Reserving the scrollbar width for hidden list views: not reliable; on GTK2
    GetSystemMetrics(SM_CXVSCROLL) returns 16 while the scrollbar takes 19 px.

GTK2 note
  The LCL default ScrollBars = ssBoth maps to GTK_POLICY_ALWAYS on GTK2: both
  scrollbars are always visible, regardless of content.

Demo
  - ListView1, TreeView1 (and StringGrid1, unchanged) use ScrollBars = ssVertical.
  - No tab-change code: the demo uses only the three standard calls.
  - README: Lazarus only (LCL-specific project, forms and packages; no Delphi
    .dfm); anchors note; scrollbar recommendation.

Verification
  - FPC 3.2.2 / LCL 3.0, GTK2, 96 and 120 DPI: no drift after resize cycles;
    ListView resized on hidden tab, then shown: no horizontal scrollbar.
  - Windows: ssVertical behaviour confirmed by the author.

Documentation
  - Spec R1-05: section 13.1 "Control configuration recommendations"
    (anchors, TListView scrollbars, grids, optional Windows OnChange call,
    GTK2 ssBoth, rejected alternatives); limitation rows in section 10;
    demo is Lazarus only (12.3); runtime tests (14); conclusions (16).
  - Static Analysis Rev H: section 7b, findings F-18..F-21.
  - RoadMap Rev E: R2-01 moved beyond 1.0, R2-02 confirmed for 1.0, R1-05
    (demo rebuild and GTK2 runtime tests).
  - Risk Analysis Rev B (file renamed from JCUISCaler_Risks_RC1.docx): update
    section for RC1.2 — status of component, technical, regression and
    environment risks after GTK2 runtime tests; record of the rejected RC1.3
    fix as a violation of critical architecture risks; rule: every code
    change is checked against section 2 before implementation.
  - RestoreInitialScale: public by design (emergency reset). Spec 8.4
    rewritten (contract, side effects, consistency), added to the API table

    RestoreInitialScale to be verified on Windows; code comment does not

2026-11-06  RC1.2 — Delphi source compatibility + fixes
--------------------------------------------------------------------------------

Delphi (unofficial)
  The source now compiles under Delphi VCL as well as FPC/LCL, with no change
  to the object-based architecture and only three {$IFDEF FPC} blocks.
  Scope: VCL only, manual integration only (copy files, add uses, three calls).
  No Delphi package is provided in 1.0; the .lpk remains Lazarus-only.
  Limitations under Delphi:
    - JCSCALER_BORDER_TAG is ignored (VCL has no BorderSpacing; Margins has
      different semantics and is intentionally not emulated).
    - Monitor/DPI change (R2-01) is not handled; VCL per-monitor DPI scaling
      may interact with the scaler on multi-monitor setups.
    - TJCUIScaler should be declared as a form field (as in the docs/demo).

File names
  - Include files renamed to JCUIScaler.capture.inc, JCUIScaler.controls.inc,
    JCUIScaler.find.inc; {$I} directives and comments updated accordingly.
    Names are case-sensitive on Linux/macOS — use them exactly as given.
    (Entries below 2026-11-06 use the previous names.)

JCUIScaler.pas
  - {$mode objfpc}{$H+} wrapped in {$IFDEF FPC}.
  - uses: removed unused units LCLIntf, LCLType, Dialogs, Buttons.
  - Added implementation-level access class TJCControlAccess = class(TControl).
    TControl.Font is protected in VCL; all generic Font access goes through it.
    Neutral under LCL.
  - ScaleControl: SavedBevel/SavedBorder initialised by assignment instead of
    initialised local variables (FPC extension). F-02 remains resolved.
  - LocalRound: Trunc(V + 0.5) replaced by Floor(V + 0.5). Identical results

    scrolled TScrollBox: -1.7 now gives -2, previously -1).
  - RestoreInitialScale: Font.Size restore via TJCControlAccess; remaining

  - JCSCALER_BORDER_TAG / TBorderOrig: comments updated (TWinControl only,

  - Redundant "Root is TControl" test removed from the BorderSpacing condition.

JCUIScaler.controls.inc
  - BUGFIX BorderSpacing apply: section moved to the start of

Documentation
